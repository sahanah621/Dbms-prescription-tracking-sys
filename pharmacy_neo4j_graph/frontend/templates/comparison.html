Core Abstraction
Modeling
Tables, Rows, Columns, Keys
Data is organized into 2D tables with predefined column types, primary keys, and foreign keys.
Nodes, Relationships, Properties
Property graph topology. Entities are nodes with labels; relationships are directed, typed first-class entities with arbitrary properties.
Relationship Storage
Modeling
Implicit via Foreign Keys
Relationships exist only as shared data values or intermediate junction tables (e.g. PRESCRIPTION_ITEM).
Explicit Double-Linked Pointers
Relationships are physical double-linked pointers stored directly in the record file without secondary index lookups.
Traversal Mechanism
Performance
Relational Table JOINs
Traversing connections requires nested loop, hash, or merge joins across table indexes. Execution time degrades as path length increases ($O(b^d)$).
Index-Free Adjacency
Traversing connections follows memory pointers directly. Execution latency is strictly proportional to the number of edges visited ($O(k)$).
Query Language
Query Mechanics
SQL (Relational Algebra)
Declarative set-oriented query language (SELECT ... FROM ... JOIN ... GROUP BY ...). Excellent for aggregations and table projections.
Cypher (Visual Pattern Matching)
Declarative graph pattern matching (MATCH (p:Patient)-[:HAS_PRESCRIPTION]->(pr) RETURN ...). Highly expressive for structural paths.
ACID Guarantees
Governance
Strict Serializability (InnoDB)
Multi-Version Concurrency Control (MVCC), write-ahead logging (WAL), row-level locks, and strict constraint validation.
Graph ACID Compliance
Fully ACID compliant through transaction log and relationship locking for interconnected operational workloads.
